# envbox — разработка

Изолированные среды на bubblewrap: консоль (bash), сетевой шлюз, ядро, GUI на GTK 4, AppImage.
Исходники разрезаны на модули (`src/envbox/`), но поставляются **одним файлом** `dist/envbox.py`.
Общаться с пользователем по-русски.

> **ИИ-агентам: сначала читайте [AI_GUIDE.md](AI_GUIDE.md)** — там подробная карта («хочу изменить X → файл → что
> проверить»), потоки запуска и сети, чек-листы, рецепты проверки без bwrap, диагностика симптомов и ловушки.
> Читать весь код не нужно. Этот файл — краткие правила сборки.

## Быстрый старт
```bash
python3 dev.py [команда…]        # запуск из исходников, без сборки (GUI, run, install, root…)
python3 build.py                 # собрать единый файл dist/envbox.py
python3 build.py --check         # проверить, что сборка проходит (ничего не пишет)
python3 build.py map             # обновить MAP.md
python3 -m unittest discover -s tests
```
`dev.py install` и `build-appimage` сами берут свежую сборку `dist/envbox.py` (нужна, потому что
установленная копия — это ещё и сетевой шлюз, который вызывает `envbox.sh`).
Править `dist/envbox.py` нельзя — он перезаписывается.

## Карта: куда идти за чем
Подробный список модулей с описаниями и именами функций — `MAP.md`. Коротко:

| Что менять | Где |
|---|---|
| Bash-запускатор песочницы (аргументы bwrap, изоляция) | `src/envbox/resources/envbox.sh` |
| Прокси с журналом, кэш DNS, подключение «наперегонки», вышестоящий прокси, мосты, канал ссылок | `src/envbox/net/` |
| seccomp-фильтр, проверка Git после работы | `net/seccomp.py`, `net/gitcheck.py` |
| Профиль среды (поля, проверка) | `core/profile.py` |
| Параметры изоляции, пресеты, рецепты установки | `core/isolation.py` |
| Каталог данных, глобальные папки | `core/root.py`, `core/rootops.py` |
| Хранение профилей и настроек | `core/store.py` |
| Запуск терминала, режимы сети | `core/terminal.py`, `core/consts.py` |
| Браузерные среды, CDP (управление Chrome) | `core/browser.py`, `cdp/` |
| Ссылки из среды наружу | `core/links.py`, `core/link_handler.py` |
| Установка в ~/.local/share/envbox | `install.py` |
| Подкоманды (`gui`, `run`, `install`, `root`…) | `cli.py` |
| Окно GUI | `gui/window.py` собирает миксины из `gui/pages/*`, `gui/browser/*` |
| Новая вкладка/страница GUI | новый миксин в `gui/pages/`, добавить в базы `EnvboxWindow` |
| Тексты, значки, CSS, `--help` | `src/envbox/resources/` (файлы, не строки в коде) |
| Версия | `src/envbox/version.py` (формат строки не менять — её читает `file_version`) |

## Правила, которые держат сборку
1. **Один файл = одно пространство имён.** Имена верхнего уровня не должны повторяться в разных
   модулях (`build.py` ругается). Приватные `_имена` тоже.
2. **Импорты только `from .x import имя` на верхнем уровне модуля.** Внутри функций относительные
   импорты не допускаются (в сборке их нет). Исключение — единственный ленивый импорт GUI в `cli.main`.
3. **Циклов нет.** Направление: `version/lazy/resources/selfpath` ← `net` ← `core` ← `cdp` ← `core.links` ← `install`/`cli`;
   `gui/*` подключаются только из `cli`. Если появляется цикл — вынести общую часть в третий модуль.
4. **GTK только в `gui/*`.** Остальное обязано импортироваться без GTK (тест это проверяет): консольные
   команды и шлюз работают без графики.
5. **Ресурсы — файлами** в `resources/`, в коде `NAME = resource_text("файл")`. Сборщик вшивает их.
6. **Состояние модуля** (`global X`) должно жить и меняться в одном модуле; `from m import X` копирует
   значение, а не ссылку.
7. После правок: `python3 build.py && python3 -m unittest discover -s tests`. Тест
   `test_dist_is_up_to_date` падает, если забыли пересобрать `dist/envbox.py`.
8. Менялось поведение установленных файлов (envbox.sh, шлюз) — поднять `ENVBOX_VERSION`.
9. **Быстрый вход шлюза.** `version`, `lazy` и `net/*` собираются в начало `dist/envbox.py` со своими импортами,
   сразу за ними — `if … in NET_COMMANDS: sys.exit(net_main())`. Эти команды (прокси, мост, seccomp, проверка Git)
   запускаются при каждом старте среды и каждой команде внутри неё, поэтому они обязаны стартовать за ~15 мс.
   Для этого в `net/*`: нельзя импортировать `core`/`cdp`/`gui`; тяжёлые модули (`asyncio`, `json`, `re`, `socket`,
   `ipaddress`, `threading`, `signal`, `urllib.parse`, `base64`, `datetime`) подключаются через `from ..lazy import …`
   (без `as`: сборщик вырезает такие импорты), `argparse` и `subprocess` — не использовать на верхнем уровне.
   Проверяет `tests/test_net.py::FastEntry`.
10. Версия Python обновилась — `envbox.pyc` перестаёт читаться. Рядом лежит метка `envbox.pyc.python`; `envbox.sh`
    берёт `.pyc` только если метка совпадает с `readlink -f /usr/bin/python3`, а `compile_installed()` пересобирает его.

## Как устроена сборка (build.py)
Модули в порядке зависимостей склеиваются, `from .x import y` вырезаются, стандартные импорты
поднимаются наверх, `resources` заменяется словарём со вшитыми файлами, `selfpath.BUNDLED` становится
`True`, `gui/*` заворачиваются в `_build_gui()` (как в исходной однофайловой версии).

## Ограничения окружения
Внутри песочницы Claude нельзя поднять bwrap (вложенные user namespace) — проверка запуска сред
(`dev.py run …`) возможна только на обычной системе.
